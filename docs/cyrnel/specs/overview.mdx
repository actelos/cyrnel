`@cyrnel/sdk` is the TypeScript package every cyrnel module is written against.
It defines the data shapes cyrnel exchanges (services, tools, execution
state) and the interfaces that adapter and environment modules implement.

## Who implements what

- **Adapter authors** implement [`AdapterModule`](/cyrnel/specs/adapter-module).
- **Environment authors** implement
  [`EnvironmentModule`](/cyrnel/specs/environment-module).
- **Cyrnel itself** implements [`EnvironmentBindings`](/cyrnel/specs/environment-bindings),
  which is what an environment module *calls into*.

## Module Manifests

Every module exposes a manifest (id, name, type, description, config and
secrets schemas) plus an `instantiate` factory. Where the manifest lives
depends on how the module ships:

- **Built-in modules** ship the manifest as a code export alongside
  `instantiate`:
  
  ```ts
  export const manifest = {
    id: "my-adapter",
    name: "My Adapter",
    type: "adapter" as const,
    description: "Hello World",
    ...
  };
  
  export function instantiate(): AdapterModule {
    return new MyAdapter();
  }
  ```

- **Custom modules** declare the manifest in `module.json` instead. The
  code file only needs to export `instantiate()`.

Built-ins are registered by cyrnel from their workspace exports. Custom
modules are loaded from `$CYRNEL_DATA_DIR/modules/<name>/` based on a
`module.json` file. See
[Writing a custom module](/cyrnel/specs/writing-custom-modules) for more info.

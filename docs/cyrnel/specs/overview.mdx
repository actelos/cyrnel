`@cyrnel/sdk` is the TypeScript package every cyrnel module is written against.
It defines the data shapes cyrnel exchanges (services, tools, execution
state) and the interfaces that adapter and environment modules implement.

## Installation and Usage

To use the cyrnel SDK in your typescript codebase, install the [`@cyrnel/sdk`](https://www.npmjs.com/package/@cyrnel/sdk)
package and use it.

```bash
npm install @cyrnel/sdk
```

## Who implements what

- **Adapter authors** implement [`AdapterModule`](/specs/adapter-module).
- **Environment authors** implement
  [`EnvironmentModule`](/specs/environment-module).
- **Cyrnel itself** implements [`EnvironmentBindings`](/specs/environment-bindings),
  which is what an environment module *calls into*.

## Module Manifests

Every module, built-in or custom exposes a tiny manifest plus an
`instantiate` factory:

```ts
export const manifest = {
  id: "my-adapter",
  name: "My Adapter",
  type: "adapter" as const,
  description: "Hello World",
  ...
};

export function instantiate(): AdapterModule {
  return new MyAdapter();
}
```

Built-ins are registered by cyrnel from their workspace exports. Custom
modules are loaded from `$CYRNEL_DATA_DIR/modules/<name>/` based on a
`module.json` file. See
[Writing a custom module](/specs/writing-custom-modules) for more info.

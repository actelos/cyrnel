`openapi` is the adapter shipped with MCI. It turns an OpenAPI document
into a service whose tools correspond to operations.

- **Workspace**: `packages/modules/openapi` (`@mci/openapi`)
- **Module type**: `adapter`
- **Module id**: `openapi`

## Usage

Install a service whose definition is an OpenAPI document:

```bash
curl -X POST http://localhost:7687/services/install \
  -H 'content-type: application/json' \
  -d '{
    "id": "petstore",
    "source": "https://petstore3.swagger.io/api/v3/openapi.json",
    "adapter": "openapi"
  }'
```

MCI will:

1. Download the URL.
2. Hand the body to `openapi.generateDefinition(content)`.
3. Persist the resulting `ServiceDefinition` (with one tool per operation).

Each tool gets:

- `id` — derived from the OpenAPI `operationId` (validated as a TypeScript
  identifier).
- `name`, `description` — derived from the operation.
- `inputSchema` / `outputSchema` — derived from request/response shapes.
- `adapterDomain` — carries the bits the adapter needs at invoke time
  (route path, HTTP method, content type expectations).

## Service-level fields

- `configSchema` describes per-service configuration like base URL
  overrides.
- `secretsSchema` describes credentials the service needs (e.g. API keys,
  bearer tokens).
- `adapterDomain` on the service carries top-level OpenAPI metadata used
  to resolve servers and security schemes.

## Limitations of the current build

The OpenAPI adapter is intentionally a thin reference implementation. In
the current code its `invoke()` returns `{ status: "200" }` without
actually issuing the HTTP request — the wiring for outbound calls is the
next step. Treat the module today as the **definition pipeline**: it
parses, validates, and surfaces operations, but it does not yet make
network calls on your behalf.

Track progress in `packages/modules/openapi/src/index.ts` — when
`invoke()` grows past its placeholder, this page will be updated.

## When to use it

- You already have an OpenAPI document for the end service.
- You want every operation surfaced as a tool with no per-operation
  configuration.
- You don't need protocol-level features beyond JSON-over-HTTP.

For anything more bespoke — gRPC, message queues, hardware interfaces,
non-standard auth flows — write a [custom adapter
module](/spec/writing-a-custom-module).

`typescript-ivm` is the environment module shipped with MCI. It is the
default home for process code.

- **Workspace**: `packages/modules/typescript-ivm` (`@mci/typescript-ivm`)
- **Module type**: `environment`
- **Module id**: `typescript-ivm`
- **Runtime**: [`isolated-vm`](https://github.com/laverdet/isolated-vm)
  isolates, TypeScript transpiled with `typescript` (`ts.transpileModule`)

## Execution Model

Each process executes inside a fresh `isolated-vm` `Context` on an
`Isolate` with a 128 MB memory cap (default). The environment maintains a
small pool of worker slots (default size 2); additional executions are
queued internally.

User code is wrapped before execution:

```js
async function __mciMain__() { /* user code */ } __mciMain__();
```

Top-level `await` is therefore allowed. The wrapped script is compiled
into the isolate and `await`-ed by the host; the resolved value is
discarded.

Cancellation (`kill(eid)`) and timeouts both **dispose the isolate and
recreate the worker slot**. There is no soft-stop.

## What's available inside

The isolate has **no module loader, no filesystem, no network, and no
Node built-ins**. The only outbound channel is `globalThis.mci`, frozen
in place by a small prelude (`bindings.ts`). The full surface:

```ts
mci.output(data: Record<string, unknown>): void;

mci.discoverServices(input: {
  query?: string;
  limit?: number;
  enabled?: boolean;
}): Promise<{ id: string; name: string; description: string; enabled: boolean }[]>;

mci.discoverTools(input: {
  serviceId?: string;
  query?: string;
  limit?: number;
  enabled?: boolean;
}): Promise<{ serviceId: string; id: string; name: string; description: string; enabled: boolean }[]>;

mci.services[serviceId].getDefinition(): Promise<{
  name: string;
  description: string;
  enabled: boolean;
  configSchema: JSONSchema;
  secretsSchema: JSONSchema;
}>;

mci.services[serviceId].tools[toolId].getDefinition(): Promise<{
  name: string;
  description: string;
  enabled: boolean;
  inputSchema: JSONSchema;
  outputSchema: JSONSchema;
}>;

mci.services[serviceId].tools[toolId].getDocs(): Promise<string>;

mci.services[serviceId].tools[toolId].invoke(parameters: Record<string, unknown>): Promise<unknown>;
```

`console.log` and `console.error` are remapped to the environment's stdout
and stderr emitters. Objects are JSON-pretty-printed; strings pass through.

## Example

```ts
const tools = await mci.discoverTools({ query: "weather", limit: 1 });
if (tools.length === 0) {
  console.error("no weather tool installed");
} else {
  const [tool] = tools;
  const result = await mci.services[tool.serviceId].tools[tool.id].invoke({
    city: "Accra",
  });
  mci.output({ result });
}
```

## Live Reference

The environment serves its own reference doc at `GET /environment/docs`
(rendered Markdown). Per-tool usage docs are served at
`GET /tools/:serviceId/:toolId/docs` and include a copy-pasteable invoke
example.

## Tuning

The defaults live at the top of `packages/modules/typescript-ivm/src/index.ts`:

| Default | Value | Effect |
| --- | --- | --- |
| `DEFAULT_POOL_SIZE` | `2` | Number of `isolated-vm` isolates kept warm. |
| `DEFAULT_TIMEOUT_MS` | `30000` | Used when a process omits `options.timeout`. |
| `DEFAULT_MEMORY_LIMIT_MB` | `128` | Per-isolate memory cap. |

These are not yet env-driven; changing them requires editing the source.

## Limitations

- Only TypeScript / JavaScript. Other languages need a different
  environment module.
- The transpiler does **not** type-check (`strict: false`,
  `ts.transpileModule`). A program that ts-fails will still compile and
  run if it's valid JavaScript at runtime.
- `import` / `require` are not supported — no module graph. Write
  everything inline.
- No persistent state between executions. Each process starts fresh.

For a different language, runtime, or permission model, write a
[custom environment module](/spec/writing-a-custom-module).

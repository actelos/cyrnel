title: "Processes"
description: "Creating, running, and inspecting processes"

A process is a stateful execution unit in MCI. When a client submits code,
MCI creates a process with a unique process id (`pid`), runs it on the active
[environment module](/content/modules/environments), captures its output, and
exposes those outputs by `pid`. Process execution does not block the client
request unless `block: true` is set.

## Process Model

Each process is an in-memory record with the following fields:

- `pid`: unique process identifier (integer, reused after deletion)
- `ref`: optional reference label (trimmed; must be non-empty if present)
- `state`: lifecycle phase (see below)
- `exitState`: execution outcome (see below)
- `error`: error message if the process failed, otherwise `null`
- `code`: the submitted source
- `options.timeoutMs`: per-process timeout in milliseconds, or `null` to disable
- `output`: structured key/value payload emitted by `mci.output(...)`
- `stdout`, `stderr`: captured byte buffers

<Warning>
  Process records are **in-memory only**. Restarting the API clears them.
</Warning>

### Process states

| State | Meaning |
| --- | --- |
| `queued` | Waiting for the environment to pick it up. |
| `running` | Currently executing inside the environment. |
| `terminating` | A `kill` signal was issued; the runtime is winding it down. |
| `idle` | Not executing. Either it hasn't been run yet, or it has finished. |

### Process exit states

| Exit state | Meaning |
| --- | --- |
| `null` | No outcome yet. |
| `success` | Code completed without throwing. |
| `failed` | Code threw, or the environment reported failure. `error` is populated. |
| `timeout` | Execution exceeded `options.timeoutMs`. |
| `canceled` | A `kill` signal interrupted the execution. |

## Create a Process

`POST /processes`

```json
{
  "code": "string",
  "ref": "optional string",
  "block": false,
  "options": {
    "timeout": 30000
  }
}
```

Rules:

- `code` is **required** and must be a string.
- `ref` is optional, trimmed, and must be non-empty if present.
- `options.timeout` is in milliseconds. Must be a **positive integer**, or
  `null` to disable. Default: `30000`.
- `block` defaults to `false`.

Response (`201`):

```json
{ "pid": 42 }
```

If `block: true`, MCI polls until `state === "idle"` before responding. The
HTTP status is still `201`.

## Run an Existing Process

`POST /processes/:pid/signals/run`

```json
{ "force": false, "block": false }
```

- The process must currently be `idle`.
- If the process has stored outputs (any of `exitState`, `output`, `stdout`,
  `stderr` is non-empty), `force: true` is required to overwrite them.
- `block: true` waits until the run completes.

Response (`200`): the process record.

## Kill a Process

`POST /processes/:pid/signals/kill`

```json
{}
```

- If the process is `queued`, it transitions straight to `idle` with
  `exitState = "canceled"`.
- If `running`, it moves to `terminating` first, then to `idle` with
  `exitState = "canceled"` once the environment confirms.
- If already `idle`, the call returns `409`.

Response (`200`): the process record.

## Inspect a Process

| Method | Path | Returns |
| --- | --- | --- |
| `GET` | `/processes` | `{ processes: ProcessRecord[] }` (filterable) |
| `GET` | `/processes/:pid` | the process record |
| `GET` | `/processes/:pid/code` | submitted source as `text/plain` |
| `GET` | `/processes/:pid/output` | structured output as JSON |
| `GET` | `/processes/:pid/stdout` | captured stdout as `text/plain` |
| `GET` | `/processes/:pid/stderr` | captured stderr as `text/plain` |

`/output`, `/stdout`, and `/stderr` return `409` unless the process is
`idle`.

### Filtering `/processes`

Query parameters:

- `state` — one of `idle | queued | running | terminating`
- `status` — one of `success | failed | timeout | canceled | null`
- `ref` — exact match (trimmed, non-empty)

## Delete a Process

`DELETE /processes/:pid`

The process must be `idle`. The `pid` is recycled into the pool and reused
by future creates.

## Minimal Flow

```bash
# 1. submit code
curl -X POST http://localhost:7687/processes \
  -H 'content-type: application/json' \
  -d '{"code":"mci.output({ hello: 42 });","block":true}'
# { "pid": 1 }

# 2. fetch outputs
curl http://localhost:7687/processes/1/output
# { "hello": 42 }
```

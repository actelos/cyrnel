`@mci/sdk` is the TypeScript package every MCI module is written against.
It defines the data shapes MCI exchanges (services, tools, execution
state) and the interfaces that adapter and environment modules implement.

- **Package**: `@mci/sdk`
- **Workspace**: `packages/libs/sdk`
- **Entry**: a single `src/index.ts` that re-exports everything.

The SDK is intentionally tiny — no runtime helpers, no defaults, no
opinions on transport. It is purely a **contract**: if your module
satisfies the relevant interface, MCI can run it.

## What's in the SDK

| Concept | Symbol(s) | Page |
| --- | --- | --- |
| JSON-Schema, service & tool shapes | `JSONSchema`, `ServiceDefinition`, `ToolDefinition`, `ServiceState`, `ToolState`, `InvokeInput` | [Types](/spec/types) |
| Base module contract | `Module`, `ModuleSetupContext` | [`Module`](/spec/module) |
| Adapter contract | `AdapterModule` | [`AdapterModule`](/spec/adapter-module) |
| Environment contract | `EnvironmentModule`, `EnvironmentSetupContext` | [`EnvironmentModule`](/spec/environment-module) |
| Callback surface from environment back to host | `EnvironmentBindings` | [Bindings](/spec/bindings) |
| Execution input & state machine | `ExecutionInput`, `ExecutionOptions`, `EXECUTION_STATES`, `EXECUTION_EXIT_STATES`, `ExecutionState`, `ExecutionExitState`, `ToolDocsInput` | [Execution](/spec/execution) |

## Who implements what

- **Adapter authors** implement [`AdapterModule`](/spec/adapter-module).
- **Environment authors** implement
  [`EnvironmentModule`](/spec/environment-module).
- **MCI itself** implements [`EnvironmentBindings`](/spec/bindings),
  which is what an environment module *calls into*. You don't implement
  these unless you're rewriting the host.

## Module Manifests

Every module — built-in or custom — exposes a tiny manifest plus an
`instantiate` factory:

```ts
export const manifest = {
  name: "my-adapter",
  version: "1.0.0",
  description: "Talks to my service",
  type: "adapter" as const, // or "environment"
};

export function instantiate(): AdapterModule {
  return new MyAdapter();
}
```

Built-ins are registered by MCI from their workspace exports. Custom
modules are loaded from `$MCI_DATA_DIR/modules/<name>/` based on a
`module.json` file — see
[Writing a custom module](/spec/writing-a-custom-module).

## Versioning

`@mci/sdk` follows the repo's overall semver. Until 1.0 these interfaces
should be considered movable; treat changes as ABI changes for modules
loaded at runtime.
